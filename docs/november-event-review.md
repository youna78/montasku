## モンスターが通常の卵に戻る問題

フレーム装備の純粋な処理は selectedFrameId のみを変更し、モンスターを交代しない。7日報酬を受け取ってから装備しても111が維持されるテストを追加した。

別の2経路で無意図の上書きを再現した。

1. forceStartEventEgg が、以前のモンスターを含む pendingDailyReview.rewardBaseSnapshot を残す。切り替え後にふりかえりの回答をすると、そのスナップショットの通常卵に戻りうる。切り替え時に古いふりかえりを終了するよう修正。
2. useGame の初期読み込みは、ローカル表示の後にクラウドを取得する。応答待ちに装備などを操作しても、取得開始時の状態を後から適用していた。ローカル操作の世代番号と画面離脱を確認し、古い初期化結果を破棄するよう修正。画面をまたぐ保存も共通キューにして、初期化保存と操作保存の順番を統一した。

これは報告された症状につながる再現可能な経路の修正であり、実際の操作履歴からどちらが発生したかを断定したものではない。既に失われた個体のデータは自動復元していない。

## Game Studioのwalk（承認・本体反映済み）

通常モンスターのシートを直接参照し、2種類の新しい提案を作成した。

- もみじポン：通常のプチドラを参考にした、立ち姿勢の足踏み・歩行。
- 旅するミニビースト：通常のプチビーストを参考にした、四つ足での歩行。

既存のv2案は座った姿勢が強く、歩行として読みにくかった。今回のv3は立ち姿勢・四つ足の支持姿勢を使い、頭・胴の大きさと足元を共通の倍率で正規化した。承認いただいたv3の2種類を本体のwalk参照に採用した。正規化済みシートの余白に合わせて表示サイズと足元も更新し、提案時と同じ見た目を維持した。

比較ページ http://localhost:3000/dev/november#walk-proposals では、通常・変更前・採用後を同じ速度で再生できる。2倍表示、一時停止、4コマ個別表示、横移動の切り替えに対応。
